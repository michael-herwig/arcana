# Changelog

All notable changes to this project will be documented in this file.

## [0.4.1] - 2026-09-06

_Folds the `0.3.0` and `0.4.0` sections written on 2026-09-06 that were never tagged: this is the first release carrying them, and the first release of nox._

### Added

- **Five tiers** (`adr_0017`, `hex/DESIGN.md` round 22): `low < medium < high < xhigh < max` plus `auto` ([`protocol.md` § Tier grammar](hex-core/references/protocol.md#tier-grammar)). Every pre-existing tier is shifted one step up under a new name with its behaviour unchanged — old `low` → `medium`, old `medium` → `high`, old `high` → `xhigh` — and `xhigh` and `max` stop being reserved words. The new **`low` is inline**: zero spawns, the orchestrator is the worker, for one-file changes of ≤30 lines with no structural marker; `/hex-execute low` keeps stub-first commits, writes its own `L0` evidence table, answers the `spec` + `quality` checklist itself and spawns one `L1` reviewer only when a non-doc file changed. The new **`max` is explicit only** (`--tier=max`, or `Tier: max` in a plan; never classified into): `xhigh` plus every configured adversary — the `adversary` key now takes a list — five research axes with `competitive-research` mandatory, one extra known-pitfall researcher on the aggregate join, and **usage simulation** by the new [`simulator`](hex-core/references/workers/simulator.md) persona (`first-time`, `power-user`, `adversarial`, `automation`, plus project `.agents/workers/simulator-<pattern>.md`) — `/hex-execute max`'s new `## Phase 8: Usage simulation`, a "Usage simulation" section in `/hex-review max`'s report, proposed changes at the review gate in `/hex-plan` and `/hex-architect max`
- **A shipped review checklist** (`adr_0016` C-989): [`checklist.md`](hex-core/references/checklist.md) — eight sections (`spec`, `quality`, `security`, `performance`, `docs`, `architecture`, `pitfalls`, `user-feedback`), every item a defect class with how to verify it on the diff. The orchestrator composes sections by join level into the brief's new `Checklist:` slot — `L1` `spec` + `quality`; `L2` per the `--review` axis; `L3` per seat focus; the inline `low` orchestrator answers `spec` + `quality` itself — and a seat answers every item or marks it not applicable with the reason. A `reviewer` spawn still opens `severity.md` only
- **`review.<level>.checklist`** (config v3 leaf) replaces the derived section set per level; `/hex-init` Step 4½ now seeds the `review.<level>.*` keys; the Upkeep step names three Memory candidate classes a run may propose (an always-on perspective, a `review.<level>.*` value the run's residue argued for, a recurring finding class worth a project checklist item); new audit item "Review settings tuned?" (`adr_0016` C-990)
- **nox ships** — arcana's second bundle, and the first shipped implementation of hex's [adversary contract](hex-core/references/adversary.md#adversary-contract): `nox-review` runs a `code-diff` or `plan-artifact` review under a *different* AI harness (Claude Code, Codex, Copilot CLI, OpenCode), headlessly, from an ephemeral git worktree with the repository's own instruction, hook and agent-config files neutralized. Pin it as `adversary: nox-review` in `hex.md › Preferences` and `/hex-review`'s cross-model gate has something to call. `grim add ghcr.io/michael-herwig/arcana/nox`; its own notes are in `nox/CHANGELOG.md`. **nox's version is arcana's, not its own** — one release train, one tag (D-aa): this `v0.3.0` publishes hex 0.3.0 and nox 0.3.0 together, so nox's first release carries hex's number rather than starting at 0.1.0
- The adversary contract's graceful skip now covers **any** outcome in which the adversary produced no review — the named skill unavailable, and equally a skill that ran and failed (unreachable harness, refused credentials, exhausted quota, an elapsed timeout, unclassifiable output). An empty finding list from such a run is stated to be the expected shape of a failure, never a clean pass, so a "triage is complete" gate can no longer pass silently with nothing triaged and no skip logged
- `/hex-init` audit item — "Cross-model adversary skill installed?": detects an installed skill's `hex-adversary-scopes` frontmatter marker with no matching `adversary:` pin in `hex.md › Preferences`, and proposes `adversary: <skill-name>` for adoption via pointer, folded into Step 4½'s single consent-gated diff. Reads installed `SKILL.md` frontmatter only (via `grim status --format json`, or the client's own skill install roots without grim), reaches no network, executes nothing, and never removes or overwrites a user-typed pin — the reverse case, a pin naming a skill that is *not* installed, is reported as drift rather than repaired, because a dangling pin otherwise makes every adversary pass log a skip forever with no one seeing why
- **The cross-model adversary pass is bounded by the adversary's own published contract where it states one, and otherwise by how hex invoked the call** — never by a liveness class hex asserts about the skill. Three observation modes, resolved per run: **skill-enforced**, where hex defers to the skill's verdict and keeps only a backstop started by the elapse of the skill's own published bound; **pollable background**, where hex measures a stall window from the last output growth, leaving total elapsed time unbounded; and **foreground blocking**, the fail-safe, where nothing is observable and a fixed wall clock stands in, disclosed at the gate on its own `Degraded:` line. On elapse of whichever bound the mode resolved to the orchestrator stops waiting, takes the existing graceful skip and proceeds; it terminates nothing — so the (a)/(c) backstop fires only where the invocation itself carries a settable timeout, and is nominal where the spawn carries none. A `deadline` follows the mode and never launders a skill's own outcome, and an empty finding list is still never a clean pass ([`protocol.md` § Adversary contract](hex-core/references/adversary.md#adversary-contract))
- New config key **`limits.adversary-timeout`** — integer minutes ≥ 1, default 5 — sets the pollable-background stall window and nothing else; the foreground-blocking backstop is fixed and is not this key. Its ceiling is its default, so a higher project value clamps and announces ([`config.md` § Key vocabulary](hex-core/references/config.md#key-vocabulary))
- **One clamp grammar now covers every limit's `Limits:` line**: a configured value above a limit's shipped or tier ceiling prints as `<name> <effective value> (clamped from <configured value> · <source>)`, the shape `max-workers` and `limits.adversary-timeout` both resolve to; an unclamped limit keeps the plain `<name> <value>` shape with its source in the trailing attribution ([`protocol.md` § The meta-plan approval gate](hex-core/references/protocol.md#the-meta-plan-approval-gate))
- **The `Limits:` line's `<name>` is derived from the key rather than spelled per limit** — the leaf key with `limits.` dropped and its hyphens read as spaces, `max-workers` → `workers` being the one shortening. The derivation governs that line and nothing else; `hex.md`'s own Preferences prose still spells the config keys themselves ([`protocol.md` § The meta-plan approval gate](hex-core/references/protocol.md#the-meta-plan-approval-gate))
- **A plan opts into per-WP effective tiers with one optional Status line, `- Effective-tier: derived`** — absence is pre-`adr_0012` semantics byte-for-byte, forever: never a prompt, never an error, never a migration step, never a rewrite of the plan to add the line. `derived` is the only value this version accepts; an unrecognized or empty value is a refusal with a `Fix:` line, and a marker on a plan carrying no `Verify` column is refused too, because that column is the `door` flag's only source and hand-adding the marker would flip every blank `Review` cell from `panel` to the derived breadth in bulk. **Two backstops keep the reduction honest**: the collapsed builder commits the stubs and the specification tests as its **first** commit on the WP branch and **the orchestrator** — never the builder's own prose — re-runs the project's test command at that commit and requires it to fail; and a plan in which any WP fell below its ceiling **does not reach its terminal review state** (`done`, or `landing` with a `Repo` column) until a branch-level `/hex-review` has run at no less than the plan's ceiling tier, which floors a lower `--tier` flag rather than being lowered by it ([`protocol.md` § The effective tier](hex-core/references/decompose.md#the-effective-tier))
- **Every live agent now writes its own heartbeat, so the orchestrator can tell a working agent from a hung one.** One flat directory per run at `${XDG_CACHE_HOME:-$HOME/.cache}/hex/<run-id>/hb/` — outside every checkout, never committed, never read by resume, deleted by teardown — with exactly one writer per file, always the agent the filename names. Freshness against the agent's own declared `expect_next_s` is the only grade the ladder applies: L0 fresh, L1 stale (a bounded wait plus a best-effort ping that is never a gate), L2 unresponsive (a `Warn` and never a kill — tool calls still flowing means alive-and-violating, and output that cannot be read holds the rung), L3 dead (stop over the agent-termination capability and re-spawn from `checkpoint` under a newly minted agent id, a coordinator's children first). One retry per phase; a second death in the same phase marks the work package `failed`. A coordinator is a worker like any other here — it writes its own beat and runs no ladder, the top orchestrator being the sole ladder runner at every depth ([`protocol.md` § Worker liveness](hex-core/references/protocol.md#worker-liveness))
- **A resource contract, shipped as a new conditional-load reference file** — [`resources.md`](hex-core/references/resources.md), read only when a run will actually issue a heavy command, so a parse-only project pays nothing for the whole contract. Nine sections: the measured resource profile (`/hex-init` runs the project's own documented gate once under a probed peak-RSS ladder and caches peak RSS, wall time, a `light`/`heavy` class and the derived ceiling as a `hex.md › Pointers` row), the host-global heavy semaphore and its idiom, preflight, the per-run scratch environment, the containment ladder, a per-ecosystem knob sheet, teardown, and output read as a resource signal. It is a knob sheet, not a policy — it records what a tool's knob is called and where its artifacts land, never which value a project should choose and never how to verify a project, which stays [`protocol.md` § Verification](hex-core/references/verify.md#verification)
- New config key **`limits.heavy`** — integer ≥ 1, defaulting to the ceiling derived from this host's measured profile (`1` where nothing could be measured) — **a ceiling on concurrent *heavy commands*, never on agents**. It is an additive leaf under the existing frozen `limits` key, neither a rename nor a seventh top-level key. Its default is its ceiling, so a higher project value clamps and announces ([`config.md` § Key vocabulary](hex-core/references/config.md#key-vocabulary))
- Three `/hex-init` audit items, folded into Step 4½'s single consent-gated diff: **"Resource profile measured?"** — runs the project's documented gate once under the measurement ladder and writes the profile row — **"Agent worktrees excluded from watchers and indexers?"**, and **"Scratch / temp convention documented?"** ([`audit.md` § Audit items](hex-init/references/audit.md#audit-items))

### Changed

- **The cross-model adversary launches in the same batch as the native seat of the join it gates, never after it** (`adr_0016` C-987, `hex/DESIGN.md` round 21): the `L2` aggregate seat, or the sole leaf's `L1` at `N = 1`, in `/hex-execute`; the Stage 2 batch in `/hex-review`; the Round 1 panel batch in `/hex-plan` and `/hex-architect`. Native seats first, adversary last; no `max-workers` slot; the two clocks are orthogonal and the join waits for both, so the terminal join costs `max(native, adversary)` instead of their sum. Its actionable findings join that join's single builder fix pass; duplicates merge with attribution; a merged pass that fails verification is reverted, re-run native-only, and the adversary findings deferred — the adversary is never re-invoked (C-988). Where the harness cannot batch the call, the existing `Degraded: blocking adversary call …` line takes the suffix `; launched sequentially`
- **Migration on read, never a rewrite** (`adr_0017` C-997): `/hex-plan` writes `- Tier-grammar: 5` into the Status block; a plan without that line has its `Tier:` shifted one step up on read and disclosed on the `Tier:` line (`Tier: medium (plan, pre-adr_0017) → high`). **Config vocabulary v4**: the `<tier>` segment of `tiers.<skill>.<tier>` and `workflows.<skill>.<tier>` takes the five values and `adversary` may be a list; a block whose comment says `v3` or lower has its tier segments shifted the same way on read, announced once at the gate. No new top-level key. The effective-tier derivation is renamed with the grammar — `S` ⇒ `medium`, `M` ⇒ `high`, floors `min(T, high)` — and effective `low` is never derived
- Twelve tier files renamed per skill (`tier-high → tier-xhigh`, `tier-medium → tier-high`, `tier-low → tier-medium`) in a renames-only commit with every `## Phase` heading byte-identical; eight new tier files (`tier-low.md`, `tier-max.md` per orchestrator); `models.md` gains `low` (all `—`) and `max` columns and the `simulator` row; `/hex-init workflows` lists five forkable tiers per skill; `hex-init` Step 4 states that `review.<level>.class` supersedes a `models.overrides` `reviewer[:focus]` entry for review seats

- **Review depth is keyed on join level, never on tier** (`adr_0015`, `hex/DESIGN.md` round 20). Four levels, defined once in [`loop.md` § Review by join level](hex-core/references/loop.md#review-by-join-level): `L0` — every builder return carries a `<ID> → <path>:<line>` evidence table the orchestrator greps, no spawn; `L1` — one fast-balanced reviewer, delta-only (`git diff <base>..<head>` + the contract excerpt), one round, 10-minute budget, at every leaf join at every tier; `L2` — one deep-reasoning seat over the aggregate diff with the leaf verdicts as inputs, only where a node joins **two or more** leaves (skipped at `N = 1`), once at a decomposing coordinator's WP join and once at `/hex-execute`'s end-of-run join over the feature branch; `L3` — the trunk pass, only when `/hex-review` is invoked. A `sec`, `hot` or `door` flag, or a `risk` cell, raises a WP one level, never a round. A level's budget ends its loop with residue recorded in the handoff, never a failure
- **New config keys, vocabulary v3**: `review.<level>.{seats, class, rounds, budget-minutes, delta-only}` for `l1` and `l2`, overridden per level, never per role ([`config.md`](hex-core/references/config.md#key-vocabulary)). `review.<level>.class` wins over `models.overrides` for review seats; `limits.loop-rounds` becomes a ceiling over every level's `rounds` (default 3); `perspectives.always` adds a checklist item to the `L2` brief in `/hex-execute` and a seat in `/hex-review`'s `L3` panel. The `--review` overlay axis now selects the `L2` seat's checklist breadth (`minimal | full | adversarial`), never a seat count; `--loop-rounds` caps every level and defaults to `1` at every tier
- **The plan's `Review` column is an optional risk hint, not a budget**: `risk` or empty. Legacy cells are read, never migrated — `panel` reads `risk`, `self` and `light` are inert. The `hex-init` plan template and `/hex-plan`'s Decompose phases write the hint; the budget histogram is the effective-tier line in every plan shape
- **`hex-core/references/protocol.md` splits into a spine plus six sibling topic files, cut at `##` boundaries only, with every heading text and level preserved byte-identical so every anchor slug survives the move.** The single file was 149,072 bytes across 18 `##` sections and was read in full by every orchestrator run and every worker spawn. The spine (50,330 bytes) keeps the shared shape, tier and overlay grammar, the meta-plan approval gate, spawn-selection precedence, worker coordination (including worker liveness), traceability IDs, untrusted-text echoes, the constitution gate, the handoff contract and the upkeep step, plus a new what-moved-where pointer and load map. The six new siblings: [`loop.md`](hex-core/references/loop.md) (22,682 B) — the Review-Fix Loop and its four subsections, the Convergence contract; [`decompose.md`](hex-core/references/decompose.md) (32,146 B) — parallel-by-default decomposition, the effective tier; [`worktree.md`](hex-core/references/worktree.md) (20,315 B) — worktree work-package mechanics; [`verify.md`](hex-core/references/verify.md) (14,603 B) — verification, the scoped check, checkpoints; [`adversary.md`](hex-core/references/adversary.md) (10,396 B) — the adversary contract; [`severity.md`](hex-core/references/severity.md) (2,202 B) — finding severity
- **A new load map, in the spine, says which topic files each mode and each worker persona opens.** It is a budget rule, not a permission: a mode may follow any link, but it opens a topic file only when a phase it is running executes against that contract, never because prose mentions it. It is [`workers.md`](hex-core/references/workers.md)'s shipped "Load only what runs" rule extended one layer up, from worker personas to the contracts orchestrators read
- **The two worker personas on the review-fix loop's serial path get the deepest cut** — the path measured in `.agents/research/rca-review-fix-loop-wall-clock.md`, where every spawn used to re-read the whole 149,072-byte file for a rule of a few kilobytes. A `builder` spawn now reads 14,603 bytes (9.8% of before); a `reviewer` spawn now reads 2,202 bytes (1.5%). Every mode drops from the same baseline: `/hex-architect` to 73,012 B (49.0%), `/hex-finalize` to 64,933 B (43.6%), `/hex-review` to 107,360 B (72.0%), `/hex-plan` to 105,158 B (70.5%), `/hex-execute` to 140,076 B (94.0%); any mode running with the adversary on adds `adversary.md`'s 10,396 bytes on top
- Migration: 347 inbound `protocol.md#anchor` links across 35 files and 92 intra-file anchors were repointed to the new files, and 87 stale link labels plus 16 prose `§` citations across 27 live instruction files were corrected to name the new file. This entry and `hex/DESIGN.md`'s existing rounds keep their historical prose as written — only their link *targets* were repointed so nothing dead-ends — and `hex/DESIGN.md` round 19's old→new mapping table is their compatibility record. No past ADR needed an erratum, because every heading survived byte-identical
- **`hex/DESIGN.md` round 19** amends the single-source rule: its destination generalises from "`protocol.md`" to "the topic file in `hex-core/references/` whose consumer set it serves," with the rule's substance unchanged, and adds the new binding "Load only what runs" rule, the old→new section map, and a considered-and-not-deviated paragraph
- The **Implement-phase gate is the scoped check** — the work package's own contract tests plus the project's cheapest documented assembly gate — unconditionally, at every tier, replacing three competing phrasings ("for changed files", "each work package's changed files", "across the whole workspace") with one. The Implement gate at tier `high` no longer verifies the whole workspace before merge — tier `high`'s Stub gate still compiles it; a defect in a module no package touched is caught by the checkpoint (three merges, a cleared dependency level, or a high-risk merge) and attributed by the bounded bisection the schedule log already makes free. Separately, the Review-Fix-Loop exit gate now runs the work package's *resolved* verification, so a `Verify: full` cell budgets one merge boundary — that gate and the merge that follows it — instead of the merge alone. The loop's exit gate is no longer conflated with the run's terminal final gate, which stays mandatory, un-lowerable by any per-package budget, and reached by every run that completes
- The **review-budget guard runs in both directions**, stated once and linked from the tier files instead of restated in each. Upward is unchanged — `self` or `light` on a security-sensitive, hot-path, large or cross-area package is a plan defect — and downward is new: a full `panel` on a size S or M, single-area package whose expected file set carries no security-sensitive and no hot-path file is equally a plan defect, because it buys nothing and costs a wave. The declared file set is the discriminator in both directions, and both are raised against the plan at the Decompose gate, never at merge time. A one-line budget histogram (`S:light 2 · M:panel 1 · L:panel 3`) prints at that gate and in `/hex-execute`'s announce block, so a plan that never varies its budgets is visible before it is executed
- **Project rules contribute perspectives, research axes, path-triggered escalations and model overrides — never a phase or a stage.** Hints populate phases; they never define them. The phase set is the resolved tier file's, rewritten only by `tiers.inherits` or `workflows`, and a rule naming an absent phase is dropped warn-once as before. What is new is the other half, which nothing stated: running a stage absent from the resolved tier file is a spec violation, announced to the same standard a silent model escalation is
- **The orchestrator reads the plan in full once; a worker brief carries the excerpt, never the plan body.** The excerpt is exactly the work package's row and its own `## Implementation Steps` entries, the contracts its scope names with the UX scenarios those reference, the changed-file list or diff, and the project-rule pointers for that worker's area; the plan path may be named for reference. The reviewer spawn template gains the contract-excerpt field it lacked, and the builder, tester and coordinator templates' existing plan-section fields are pinned to the same itemization
- **Two merge-gate checkpoint mechanics now narrow to the merge gate's own runs**, so an in-worktree check can no longer confuse them: merge rule (v)'s escalation to full verification now fires only on a degrade **in the merge gate's own run** of the scoped check or the selective-test convention — a degrade at the Implement gate or the Review-Fix Loop's in-worktree exit gate binds that run alone and never escalates the merge gate. Separately, the `M = 3` checkpoint counter now resets only on a full documented verification run **at a merge gate**: neither a Review-Fix Loop exit gate nor a coordinator's in-worktree join check resets it, and a bisection probe — a diagnostic re-run at an already-recorded SHA — never resets it either ([`protocol.md` § Worktree work-package mechanics](hex-core/references/worktree.md#worktree-work-package-mechanics) and [§ Verification › Checkpoints](hex-core/references/verify.md#checkpoints))
- **The `Size` column is promoted from pure reporting vocabulary to a read cell**: the downward [budget guard](hex-core/references/decompose.md#parallel-by-default-decomposition) now reads it as one conjunct alongside `Expected Files`, which stays decisive; a missing `Size` column or cell defaults to `L` for that guard, so a pre-`Size` plan behaves unchanged, and the budget histogram omits an unsized work package rather than asserting a size nobody wrote
- **Merge rule 9 now separates a malformed value from an out-of-range one.** Malformed is a wrong type, a value outside a non-numeric key's stated vocabulary, or a value below the floor the key's `Type` column states — alongside an unparseable glob, an unknown role, an unknown skill/tier/phase segment, and an unreadable `workflows` path — and keeps the ignore-that-key-only, keep-the-default, warn-once handling, so `limits.adversary-timeout: 0` is malformed. A **well-formed value above a limit's ceiling is not**: it clamps to that ceiling and the clamp announces, and a limit whose row names no ceiling — `limits.artifact-loop-rounds` — honours the value as written ([`config.md` § Merge rules](hex-core/references/config.md#merge-rules))
- **Worker-brief excerpting (universal rule 8) gains two carve-outs**: a worker whose target *is* the artifact — a `reviewer` running in `plan-artifact` scope, or a `builder` reading the plan or ADR file its own `Expected Files` names — reads that artifact in full rather than the excerpt, since there it is the diff under work, not context; and an `architect` reads in full the ADR or standalone design document its brief names as its compliance target, never the plan, since an excerpt cannot establish conformance to what it omits. Every other plan or ADR still reaches a worker as the excerpt ([`workers.md` § Universal worker protocol](hex-core/references/workers.md#universal-worker-protocol) rule 8)
- **Every tier now schedules the run's final gate explicitly** — a `Gate` line naming merge-rule trigger (iii) fires once at the end of the run, however many work packages merged, a single-package plan included, so a run can no longer complete having scheduled no full documented verification anywhere ([`protocol.md` § Worktree work-package mechanics](hex-core/references/worktree.md#worktree-work-package-mechanics))
- **`/hex-plan` now emits the `Verify` column in every WP-table it authors** — the authoring skill's column enumeration previously omitted it, so a freshly planned table never carried the cell C-924 had just widened to govern two gates ([`protocol.md` § Parallel-by-default decomposition](hex-core/references/decompose.md#parallel-by-default-decomposition))
- **The plan template's Before-Merge Definition-of-Done checkbox now names the merge gate's own check** — the scoped check, or full verification on a documented trigger — replacing the stale "the project's documented verification passes" line the scoped-check rewrite left behind ([`protocol.md` § Worktree work-package mechanics](hex-core/references/worktree.md#worktree-work-package-mechanics))
- **`limits.loop-rounds` is typed `int ≥ 1`**, widened from `int 1–3`. The tier default is the key's ceiling, so a higher value clamps and announces under merge rule 9 rather than being rejected as malformed, and the `Type` column no longer restates a bound the ceiling owns ([`config.md` § Key vocabulary](hex-core/references/config.md#key-vocabulary))
- **The plan's tier is now a ceiling and every work package derives its own effective tier** — from its `Size` cell and a closed set of four risk flags (`sec`, `hot`, `hub`, `door`), never authored, never above the ceiling — and that effective tier, not the plan tier, drives four axes: which phases run, which `models.md` cell each WP-scoped spawn reads, review breadth, and the loop-round cap. At effective tier `low` the pipeline **collapses**: Stub, Specify and Implement become one builder spawn and Verify-Architecture does not run, with the committed-stub check above standing in for the hand-offs it removes; effective `medium` and `high` are unchanged in every byte. The `Review` column's direction **flips** — raise-only against the derived breadth instead of lower-only against the tier baseline — so `panel` is the one escape hatch, raising the WP to the ceiling on all four axes, while `self` and `light` go inert in a plan carrying the marker. **The risk flags fail closed**: a flag whose source is absent, unreadable or malformed reads `true`, so a project that has attested nothing runs every WP at the ceiling and buys nothing until it writes one `hex.md › Pointers` row — the speedup is opt-in, and the safe default costs no coverage ([`protocol.md` § The effective tier](hex-core/references/decompose.md#the-effective-tier))
- **The concurrency cap now counts live model-compute rather than live agents.** An agent in the declared state `blocked` carrying a `blocked_on` value does not occupy a slot, which is what keeps nested fan-out from deadlocking against the pool its own children draw from. The exemption rides on the declared state and never on an inference — a `blocked` beat without `blocked_on` still occupies its slot — and recursive counting, the effective cap `min(8, max-workers)`, the clamp and the federated single-lead read are unchanged ([`protocol.md` § Worker coordination](hex-core/references/protocol.md#worker-coordination))
- **The coordinator gate splits in two, making per-work-package sub-orchestration the default.** Q1 asks whether a work package gets a coordinator at all — yes when the ready set holds ≥ 2 work packages and the harness can nest — and Q2 is the existing ≥ 3-independent-sub-task judgment, now deciding only whether that coordinator further decomposes. [`coordinator.md`](hex-core/references/workers/coordinator.md)'s Mission is the sole definition site for the two kinds, **pipeline** and **decomposing**, and every `coordinator-owned` rider retargets to the decomposing kind alone: the `join` full-verification trigger, the `M = 3` checkpoint-counter reset, the two scoped-check gate sites and the leaf-under-a-coordinator carve-out — a pipeline coordinator has no join, so leaving that carve-out on it would have degraded every Implement gate to a compile-only check with nothing behind it. Breadth is decoupled from coordinator existence: a coordinator work package is no longer `panel` by definition, and review breadth stays the package's own budgeted `Review` against its effective tier. A pipeline coordinator's capability class follows its work package's effective tier with all three cells filled, while a decomposing one keeps `deep-reasoning` and its medium/high tier gate ([`hex-execute/SKILL.md` § Coordinator spawn](hex-execute/SKILL.md#coordinator-spawn), [`models.md` § The matrix](hex-core/references/models.md#the-matrix))
- **The plan's `## Schedule log` gains a second line kind, and with it the run's telemetry.** Alongside the existing `merged` line, a `phase` line records the work package and phase, the capability class, work elapsed and — bracketed, so each is simply absent where its start is unknown — wait elapsed and review rounds. The two kinds are discriminated by the first word after the first `·`, so consumers that read only `merged` lines are unaffected. One writer, one place: the parent renders both lines from its own timestamp brackets and from each coordinator's existing structured return ([`protocol.md` § Parallel-by-default decomposition](hex-core/references/decompose.md#parallel-by-default-decomposition))
- **An execution run's handoff block now carries a timing rollup — six figures, read from the plan the run just wrote**: total wall clock, per-work-package wall clock, per-phase wall clock, the work/wait split, review rounds and adversary-gate time. - A scoped remote-rights amendment: hex's "never pushes" rule is now "never pushes except `/hex-finalize`'s force-push of the one feature branch it was invoked on, after its gate", defined once in `hex-core/references/finalize.md` — the act set, consent model, force-push mechanics, backup-ref lifecycle, degrade ladder, and trust classes for convention inputs

It reads project context and checked-in files only, reaches no network, and recommends target-branch protection as the control that actually holds
- `/hex-review` hands an approved branch off to `/hex-finalize`
- A `Verify` column on the plan's work-package table (`scoped | full`) — plan-time, raise-only, for a work package whose merge deserves the full suite because it changes a default, a schema or a config value nothing textually references, which the merge-time risk predicate cannot see
- A `- Reviewed: <sha>` Status-block anchor and delta-scoped review rounds — a round reads what changed since the last round, plus the files the previous round's findings named, instead of re-reading the whole branch every time. The anchor is range-validated before use and falls back to a full-branch review when it fails; one full pass at the converged gate stays mandatory and cannot be lowered
- `## Schedule log` — an append-only plan section, one line per merge: time, work package, post-merge SHA, which gate ran and why, and the ready and blocked sets. It makes a ready-set that never widens visible as drift, and it makes a failed checkpoint bisectable. It replaces the plan template's never-written `## Progress Log`
- A selective-test-command convention — a `/hex-init` audit item ("Selective test command documented?") plus two `hex.md › Pointers` homes: where that command is documented, and where the project's security-sensitive / hot-path convention lives. hex substitutes `{base}` and `{files}` textually and never rewrites the command into a tool's flag dialect
- A stranded-work-package report at the end of a run: the failed work package first, then every package that never became eligible, each naming its direct blocker. `/hex-review` withholds the terminal Approve state — `done`, or `landing` for a federated plan — while a run ends with a non-empty stranded set

### Changed

- The per-merge gate: a work-package merge onto the feature branch now runs a scoped check — that package's own contract tests plus the project's cheapest documented gate proving the merged tree assembles — rather than the project's full documented verification. Full verification still runs on the documented triggers (a coordinator join; a checkpoint, which fires three merges after the last full run, on a cleared dependency level, or on a high-risk merge diff; and the final gate) and on the overrides (a `Verify: full` cell, or a degrade where no scoped check can be assembled). The final gate is unchanged and un-lowerable
- The failure cascade no longer halts the wave: a failed work package is still marked `failed`, but the run continues while any package is eligible and escalates at the end with the stranded set. A failure caught at a checkpoint is bisected over the merges since the last full run — the schedule log's SHAs make that free — and the escalation names the culprit, not the window
